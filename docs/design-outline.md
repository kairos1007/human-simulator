# 人类模拟器设计纲要 v0.2

**2026 年 11 月 21 日 · 研发草案**（v0.1 写于 11 月 20 日）

这份纲要只管方向和顺序。「人」具体怎么定义，写在[白皮书](whitepaper/README.md)里。

## v0.2 改了什么

- **顺序反过来**：v0.1 是先跑合租屋 demo，再从跑过的案例写白皮书。v0.2 改成先把「人」定义完，写成白皮书，再运行。
- **合租屋不再是第一步**：它只是验证阶段的候选场景之一，到那时再选。
- **状态层和记忆层并列**：v0.1 以关系历史（记忆）为中心。11 月 21 日的想法是，状态指示器可能比追溯记忆更直接地决定一个人怎么做。两者都要定义，谁更关键留给验证阶段回答。
- **删掉了筹资和路演安排**：等有了可以展示的东西再写。

## 原则

1. **先定义人，再运行。** 人还没定义完就让 AI 跑起来，跑出来的性格是模型自带的，不是我设计的。
2. **规则由我自己写。** AI 可以帮我整理、检索和实现，规则和逻辑不外包。
3. **先模拟现实，再谈架空。** 连现实都模拟不了，架空世界只会出现为了故事而违背人物内心的行为。
4. **从一个人开始。** 一个人像人了，两个人的交互才有意义。
5. **全程公开，开源。** 想法、卡点和改过的决定都写下来。

## 路线

| 阶段 | 做什么 | 怎么算完成 |
| --- | --- | --- |
| 一、定义一个人 | 按白皮书的层（底色、认知、记忆、状态、关系、决策、表达）逐层写规则 | 每一层都写完，并通过纸面推演 |
| 二、白皮书 v1 | 把各层规则和它们之间的影响写成一份完整文档，公开到 GitHub | 别人只读白皮书，就能手推出一个人在某个情境下的选择 |
| 三、运行一个人 | 按白皮书做第一个可运行版本，场景届时再选 | 只改一个输入，选择就变了，而且能指出是哪条规则在起作用 |
| 四、两个人 | 两个人各自决定，彼此的决定成为对方的处境 | 两个人各自记住了什么、关系怎么变，都能追溯 |
| 五、一个家、一个小镇 | 接入世界层（事件、环境、信息流转） | 待定 |

现在处于**阶段一**。

## 纸面推演

阶段一、二不让 AI 执行。检验规则用编剧的办法：围读。

1. 写完一层规则，挑一个情境。
2. 在纸上手推：这个人此刻的读数是多少，他想起了什么，按规则他会怎么选，心里那句话是什么。
3. 换一个输入（比如只换能量，或只换一段过去）再推一次。
4. 推不出来、推出来不像人，或者两次的差别解释不了，就说明这一层还没定义完。

每次推演都记下情境、输入、推出的选择和卡住的地方，这些也是公开内容的素材。
